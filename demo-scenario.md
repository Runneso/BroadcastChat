# Demo: BroadcastChat — сценарий проверки

## Предусловия
- JDK 22+, Maven 3.9+
- Сборка проекта выполнена:
```bat
mvn -DskipTests package
```

## 1. Запуск серверов
Откройте два отдельных окна терминала:
```bat
mvn exec:java "-Dexec.mainClass=chat.server.Main" "-Dexec.args=A 127.0.0.1 9001"
```
```bat
mvn exec:java "-Dexec.mainClass=chat.server.Main" "-Dexec.args=B 127.0.0.1 9002"
```

## 2. Запуск балансировщика
В третьем окне:
```bat
mvn exec:java "-Dexec.mainClass=chat.balancer.Main" "-Dexec.args=5000 config.json"
```
- Убедитесь, что `config.json` содержит обе ноды, например:
```json
{
  "servers": [
    {"serverId":"A","host":"127.0.0.1","port":9001},
    {"serverId":"B","host":"127.0.0.1","port":9002}
  ]
}
```
- Балансировщик начнёт health‑check и разошлёт `SERVER_LIST_UPDATE`.

## 3. Запуск клиентов
В двух новых окнах терминала:
```bat
mvn exec:java "-Dexec.mainClass=chat.client.Main" "-Dexec.args=127.0.0.1 5000 alice"
```
```bat
mvn exec:java "-Dexec.mainClass=chat.client.Main" "-Dexec.args=127.0.0.1 5000 bob"
```
Ожидаемо: оба клиента увидят приветствие `Welcome to BroadcastChat...`.

## 4. Проверка кросс‑нода доставки (без дублей)
- В окне `alice` введите: `hello`
- Ожидаемо:
  - `alice` увидит одну строку вида `[YYYY-MM-DDTHH:MM:SS.zzz] alice: hello`
  - `bob` увидит одну строку с тем же текстом
- Введите у `bob`: `hi`
  - Ожидаемо по одной строке у обоих клиентов (без дублей).

## 5. Проверка отказоустойчивости клиента
- Убейте сервер, к которому подключён один из клиентов (например закрыть окно сервера `A`).
- Ожидаемо у клиента в консоли периодические сообщения о переподключении:
  - `No available servers. Retrying in 10 seconds.` (если все ноды недоступны)
  - либо короткая пауза и восстановление печати сообщений после переподключения
- Отправьте ещё сообщения — доставка продолжится через оставшуюся живую ноду.

## 6. Динамическое масштабирование
- Добавьте новую ноду в `config.json`, например `C:9003`:
```json
{
  "servers": [
    {"serverId":"A","host":"127.0.0.1","port":9001},
    {"serverId":"B","host":"127.0.0.1","port":9002},
    {"serverId":"C","host":"127.0.0.1","port":9003}
  ]
}
```
- Поднимите сервер `C` в новом окне:
```bat
mvn exec:java "-Dexec.mainClass=chat.server.Main" "-Dexec.args=C 127.0.0.1 9003"
```
- Ожидаемо: балансировщик в течение 30 секунд перечитает конфиг, сделает health‑check и разошлёт новый `SERVER_LIST_UPDATE`. Ноды установят peer‑соединения.
- Отправьте сообщения — все клиенты продолжают получать чат без дублей.

## 7. Динамическое удаление
- Удалите одну ноду из `config.json` или остановите её процесс.
- Ожидаемо: балансировщик исключит адрес, в `SERVER_LIST_UPDATE` ноды перестроят peer‑коннекты. Доставка сообщений сохраняется у оставшихся.

## 8. Проверка отсутствия дублей
- Несколько раз отправьте одинаковый текст подряд (с короткой паузой). 
- Ожидаемо: в клиенте каждая отправка отображается один раз.
- Если вручную «зафлудить» сеть повтором одного и того же `ChatMessage` — клиентская дедупликация по `messageId` не даст отрисовать дубль.

## 9. Команда выхода
- В клиенте введите `/quit` — клиент завершит работу и закроет соединение.
